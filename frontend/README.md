# Synapp frontend

React/TypeScript + Vite, Tailwind CSS, Motion, React Three Fiber and Drei. Shared controls use the existing shadcn-compatible theme and component directory; the current button is a project-owned native control, not a generated Radix component.

## Run

```sh
npm ci
npm run dev
```

Open the printed URL. The Swift API is optional for browsing: content falls back to the same version-controlled library in ../content. When the API is running, topic panels load its current topics and sources.

## Experience

- Light mode by default; dark mode persists in local storage.
- A textured MakeHuman surface and a Z-Anatomy muscle/skeleton view, with 37 clickable regions, front/back views, rotation, zoom and reset. Model downloads are bundled locally and loaded on demand.
- Keyboard-accessible region selection grouped by torso, arms and legs, plus a fallback if WebGL fails. Hover previews a body area directly on the mesh; clicking or tapping keeps it selected. Choosing a rear region from the text selector turns the body automatically, while direct body selection preserves the current viewing angle.
- Expanded issue pages, symptoms and general care grouped by condition, with original NHS and AAOS source links.
- A Questions tab checks warning signs, then branches into area-specific follow-ups based on earlier answers, alongside onset, duration, trend and daily impact. Changing an earlier choice removes answers from inactive branches. Swift returns closer symptom matches and possible overlaps with supporting and less-typical observations. Warning guidance and the library remain available offline; tailored matching requires the backend. Answers reset when the body area changes and are not saved.
- A local library companion with suggested questions. It does not call AI, interpret personal symptoms, or retain conversation after reload/region changes.
- Responsive layout and reduced-motion support. At 760px and below, a fixed bottom bar keeps Explore, Search and Tendi available while scrolling. The mobile companion panel sits above the bar, with room below page content for navigation and device safe areas.

The two body views are independent illustrative models, not aligned layers of the same person. Region selection is approximate; neither model is clinically validated. Credits and source licenses are available below the viewer and in `public/models/`. All medical content remains editorial draft. No new clinical advice is generated by the frontend.

## Checks

```sh
npm run build
npm run lint
npm test
```

In environments where Vite's default configuration bundler cannot access parent directories, its supported runner loader can be used: `npm run dev -- --configLoader runner`. Production bundles can be previewed with `npm run preview`.

The body model update was checked in a desktop browser: both views, all 37 areas, anatomical sides, front/back controls, mobile width, dark mode and a failed model download with a working text selector. A failed surface download can be recovered by switching to the muscle view. Build, lint, region-mapping and real-asset geometry tests also pass. The geometry tests require every area to have painted faces and verify that clicking a face returns the exact region ID used to shade it. Cached source geometry stays unmodified. The viewer uses demand rendering and accelerated mesh picking: idle views stop drawing, and there are no marker projections or per-marker occlusion raycasts. Continue to verify keyboard navigation, library replies, source dialogs and device-specific WebGL behavior before release.
